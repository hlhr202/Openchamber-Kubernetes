إضافة Kubernetes لـ OpenChamber. يمكنك تصفّح العناقيد وتشخيص مشكلات أحمال العمل وتنفيذ عمليات Kubernetes الشائعة دون مغادرة مساحة عمل مشروعك.

## التثبيت

بعد نشر ملفات الإضافة المبنية مسبقًا على الفرع الافتراضي للمستودع:

1. افتح **الإعدادات ← الإضافات** في OpenChamber.
2. ألصق عنوان المستودع في حقل **مجلد أو ZIP أو URL** ثم انقر على **إضافة**:

   ```text
   https://github.com/hlhr202/Openchamber-Kubernetes
   ```

3. راجع إذن استخدام الخدمة المحلية المطلوب وامنحه، ثم افتح **Kubernetes** من شريط الإضافات.

لا حاجة إلى بناء الإضافة محليًا أو تثبيت تبعيات JavaScript. ما دام المستودع خاصًا، يجب أن تكون لدى OpenChamber Server بيانات اعتماد Git تتيح قراءة المستودع عبر HTTPS. تسجيل الدخول إلى GitHub من المتصفح لا يوفّر هذه البيانات للخادم.

يتوفر أيضًا ملف ZIP مبني مسبقًا للتثبيت اليدوي من [النسخة المرشحة التي جرى التحقق منها في Docker](status.md). لم يُتحقق بعد من التثبيت عبر عنوان Git.

## المتطلبات المسبقة

- **OpenChamber 2.5.1**، وهو الإصدار المستهدف لهذه الإضافة.
- ملف **kubeconfig** صالح ومتاح لمستخدم نظام التشغيل الذي يشغّل OpenChamber Server، مع إمكانية الوصول عبر الشبكة إلى واجهة Kubernetes API والأذونات اللازمة للعمليات التي تريد تنفيذها.
- يجب أن تتوفر أداة **`kubectl`** على الخادم. العمليات التي تستدعي واجهة Helm CLI تتطلب **Helm**. وإذا كان kubeconfig يستخدم أداة خارجية لبيانات الاعتماد، فيجب أن تكون هي أيضًا متاحة على الخادم. لا تثبّت الإضافة هذه الأدوات.

## الميزات

- بدّل بين سياقات Kubernetes ومساحات الأسماء، وتصفّح أحمال العمل والخدمات والموارد المخصّصة في شجرة الموارد.
- افحص ملفات بيان الموارد، واقرأ سجلات Pod، واعرض أحداث مساحات الأسماء.
- راجع تغييرات ملفات البيان وطبّقها بأمر صريح على الهدف المحدد.
- افتح طرفية في الحاوية المحددة أو اضبط إعادة توجيه المنافذ.
- تصفّح مستودعات Helm ومخططاته وإصداراته وسجل مراجعاته.

## ما اختبره المؤلف

اختبر المؤلف بنفسه أربع حالات فقط: توسيع القوائم في شجرة الموارد، وعرض تفاصيل الموارد، واستخدام طرفية الحاوية، وإعادة توجيه المنافذ. إذا واجهت مشكلة أو كان لديك سؤال حول استخدام آخر، يمكنك [فتح بلاغ على GitHub](https://github.com/hlhr202/Openchamber-Kubernetes/issues).

## الخصوصية

- لا ترسل الإضافة بيانات قياس عن بُعد أو بيانات تحليلية إلى مطوريها. وهي تستخدم kubeconfig على الخادم للاتصال بواجهة Kubernetes API المضبوطة وفقًا لأذوناتك الحالية.
- تبقى بيانات الموارد المسترجعة والسجلات ومخرجات الطرفية والمسودات غير المحفوظة في الذاكرة ولا تُكتب على القرص. تحفظ الإضافة التفضيلات غير الحساسة، مثل اختيار مصادر kubeconfig، ولا تحفظ محتواها. الحفظ أو التصدير بطلب صريح عمليتان منفصلتان.
- لا تُعرض قيم Secret إلا عند طلبها، ووفقًا لأذوناتك في Kubernetes. لا تُرسل بيانات العنقود تلقائيًا إلى المحادثة أو إلى مزوّد النموذج.

ينطبق هذا البيان على الإضافة فقط، لا على OpenChamber أو Kubernetes أو الأدوات والخدمات الخارجية التي تستخدمها.
