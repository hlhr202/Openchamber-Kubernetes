# Helm Repositories, Charts, and Releases

- **M6-F1/F2:** `Helm Repos → repo → chart → version` reads existing configuration and indexes without writing. Report a missing index explicitly. Refresh requires user action and writes only to an isolated cache. It does not change repository configuration. Expanding the tree does not download anything.
- **M6-F3/F6:** Distinguish viewing Inspect and Dependencies, generating files with Fetch Values, downloading and safely extracting with Fetch, and chart authoring commands such as Convert, Create, Lint, Dependency Update, Dry Run, Template/Preview, Package, Insert Dependency, Parameterise, and Version. Authorize index reads, isolated cache writes, buffer edits, server file writes, and tool execution according to their actual side effects. Do not turn every action into a preview or treat all actions as read-only automated checks.
- **M6-F4:** Bind `Helm Releases → release → revision` to context and namespace and retain status, version, and history. Parse Helm release Secrets within bounds and do not expose values in the tree. Get reads the exact revision. Use storage UID and resource version or the required snapshot to identify same-named replacements.
- **M6-F5/F7/F8:** Install, Rollback, and Uninstall bind the release generation, revision or values, target, and confirmation. Do not add a separate Upgrade action. Server-side Helm writes do not materialize a kubeconfig. The token is limited to the child process environment, and a restricted temporary file containing the public CA is used only if necessary. Do not install tools or log in automatically. Preserve unknown results and errors; refresh on success. CLI checks before and after execution do not promise atomicity.
