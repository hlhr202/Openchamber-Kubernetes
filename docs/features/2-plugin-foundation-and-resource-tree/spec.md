# Plugin Shell and Resource Tree

- **M2-F1/F9:** The official rail panel and page share the resource tree workbench and the same UI and service bundle. Honor the host language, theme, and accessibility settings while keeping tree group names in English. See the [design spec](../../design.md) for geometry, layout, and states.
- **M2-F2/F8:** Discover contexts and namespaces on the server from the default source, one file, or an explicitly ordered set of files. Reject stale identities and results when the source, order, content, or actual target changes. Distinguish missing references, unavailable authentication, and empty configuration. Selecting a source does not authenticate it. See the [workspace architecture](../../architecture.md#project-workspaces-and-reads) for lifecycle rules.
- **M2-F3–F7:** Show fixed groups under the active context and read branches on demand. Namespace is a leaf. Node shows the Pods on that node across namespaces. Deployment, StatefulSet, DaemonSet, Job, and Service expand to Pods using valid selectors; an invalid selector never means all Pods. Do not add a Jobs level under CronJob. Pod details show phase, readiness, and IP. ConfigMap and Secret expand to keys only. CRDs and Helm retain their own identities and pagination; see [Explorer](../9-resource-explorer-ux-and-request-control/spec.md) and [Helm](../6-helm-repositories-and-releases/spec.md).
- **M2-F10–F13:** Use a fixed toolchain to produce installable candidates, isolated verification, and reproducible build measurements. A standalone synthetic bootstrap is not plugin verification. See [development](../../development.md) for commands and limits.
