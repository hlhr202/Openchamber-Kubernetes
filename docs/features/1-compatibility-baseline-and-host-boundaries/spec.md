# Compatibility Baseline and Host Boundaries

- **M1-F1–F4:** Match the pinned VS Code Kubernetes `1.4.1` [sources](../../baseline/sources.json), [registration inventory](../../baseline/upstream-inventory.json), and [command coverage fixture](../../baseline/command-coverage.json). Check reachable entry points, applicable nodes, parameters, execution, side effects, cancellation, and results. Menu names and legacy code alone do not establish behavior. A separate Clouds view and internal activation commands are out of scope. Measure visual parity separately using the [design spec](../../design.md).
- **M1-F5–F7:** Rely only on the pinned public interfaces of the official host and SDK. Distinguish the development runtime, actual host runtime, and target platform. Identify side effects of authentication, caches, external tools, and providers. Source review and environment setup do not count as runtime evidence.
- **M1-F8:** Keep unmet capabilities explicitly blocked. Do not work around them by patching the host, adding placeholders, or quietly reducing scope. Follow the [architecture](../../architecture.md) and [acceptance spec](../8-integration-packaging-and-human-acceptance/spec.md).
