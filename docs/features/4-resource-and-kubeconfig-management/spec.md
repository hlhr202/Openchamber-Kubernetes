# Resource, Document, and Kubeconfig Writes

- **M4-F1–F3:** Distinguish a live document, an editing draft, and a server file. Save is not Apply. Diff does not run a write dry run. Create, Apply, Delete, and file operations each bind their own target and confirmation. Pod Delete Now is not force deletion. Apply chooses a permitted diff strategy for the object type. Applying one file supports up to 16 documents, up to 1 MiB each, with per-document preview and confirmation. Do not scan directories in bulk.
- **M4-F4–F6:** Offer Scale, Run CronJob Now, and Expose only for applicable resources. Run builds, pushes, and runs in that order; do not advance when the previous result is unknown. Sync resolves a Git commit from the container image tag and checks it out after confirmation. It does not upload or Apply. Adding or deleting a ConfigMap or Secret key preserves the other keys. Verify an overwrite and obtain confirmation first.
- **M4-F7/F8:** Set Kubeconfig manages server-side sources. For ordinary Use Context and Use Namespace actions, the menu choice is explicit intent and needs no second confirmation. Both still use bounded submission and query the original result. Use Context changes only `current-context` in the first existing file among the selected sources. Use Namespace changes only the file that defines the active context and does not write an already selected value. Refresh only after confirmed success and configuration readback. After a namespace switch, reopen only previously open built-in lists, in order, without reusing old rows, cursors, or watches. Check shared references before deleting configuration. Report dependent steps and partial success separately when deleting the current namespace.
- **M4-F9:** All write entry points use the [shared write gate](../../architecture.md#writes-sessions-and-data). Configuration writes also check the source and version and enforce serialization. Do not replay an unknown result. A refresh failure after confirmed persistence is not a write failure or rollback. The user decides overwrite conflicts. Record the outcome against the original target.
