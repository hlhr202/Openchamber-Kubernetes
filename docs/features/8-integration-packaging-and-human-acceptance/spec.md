# Packaging and Manual Acceptance

- **M8-F1–F5:** Trace input, confirmation, execution, results, cancellation, failures, unknown states, and cleanup by command and actual entry point. Bind the candidate ID to both the complete artifact contents and build inputs. Produce reproducible ZIPs and record external dependencies, target platforms, and the actual package digest. Separate engineering checks from runtime acceptance. Case counts, bootstrap, empty workflows, and placeholder views do not prove a capability works.
- **M8-F6–F9:** A person verifies the actual installed candidate ID and ZIP digest, platform, and tool versions in a non-production environment. Record pass, fail, or not run per case and return only redacted results. Cover macOS arm64 and Linux x64 servers; desktop, web, and remote clients; installation, updates, authorization revocation, and removal; and real authentication, reads, operations, sessions, and shutdown. Independently verify presentation using the [design spec](../../design.md). Functional or synthetic DOM tests do not substitute for it. Retest affected cases when the package changes.
- **M8-F10/F11:** Report build measurements and real response performance separately. Do not assume a platform passes if it has not been tested. Follow the [hard limits](../../README.md#hard-limits) for environment and shutdown constraints. Distinguish implementation gaps from pending manual acceptance. Never start operational acceptance checks automatically.
