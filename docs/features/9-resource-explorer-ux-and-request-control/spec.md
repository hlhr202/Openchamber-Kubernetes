# Explorer Interaction and Request Boundaries

- Open on the resource tree by default. Menus list only applicable actions, and inline, context-menu, and keyboard entry points share action definitions and pre-execution target checks. A single click selects the row and sets the keyboard navigation origin. Expand with the chevron, a double-click, or the keyboard. Double-clicking does not select text or invoke a leaf action. Only an admitted read shows a spinner on its row. The row expands on success or failure; cancellation does not reopen it.
- On wide screens, the splitter between the details and tree panes supports dragging and keyboard control. It defaults to roughly 30/70 and enforces minimum widths for both panes. Keep the ratio in project memory; narrow single-column mode does not overwrite it. Type icons use existing context or resource fields and adapt to the theme. Deployment, Pod, and Helm status icons and colors take precedence. Do not guess cloud providers or make extra queries.
- Prefer `PartialObjectMetadataList` when negotiating with Kubernetes for 13 built-in list types and both Custom Resources lists: CRD definitions and instances. Project only the required identity fields. Do not fill in list rows with per-object GETs. Pod, Deployment, and Service retain full lists for status or port data. Single-object details, API discovery, Watch and relist, and Helm do not switch to this transport. VS Code's JSONPath, custom columns, and tables filter client output; they do not guarantee a metadata-only HTTP response.
- The plural part of a CRD definition name is only a type-row label. Opening a type verifies the exact CRD UID and resource version, the served GVR from live discovery, scope, and `listKind`, then rechecks the definition after listing instances. Continuation keeps the original query and LIST resource version. Metadata can still exceed the budget because of annotations, and the compatibility path may return full JSON. The receive limit stays at 2,000,000 bytes. Tree rows distinguish CRD definition-list, single-object verification, and instance-list budget failures.
- The shared read gate limits concurrency, queues, timeouts, and cooldowns. Manual reads take priority. Do not scan, paginate, or renew leases in the background. Admit Watch when there is valid list proof or an explicit refresh. Routine background sync stays silent, while errors remain visible. Project switches and viewer reattachment follow the [workspace lifecycle](../../architecture.md#project-workspaces-and-reads).
- The viewer takes its language from OpenChamber's `onReady` snapshots, including later updates to the same iframe. Use stable English message keys, bundle the 15 host locales, and fall back to English for unknown tags. Language updates repaint without using a project command or replacing the workspace. Arabic and Hebrew mirror the layout; code, logs, and identifiers keep their original text. The current catalog covers the workspace banner, primary explorer and Helm index, resource status labels, and selected task and form labels. Forms and secondary views still using older bilingual strings are not fully localized.
