Розширення Kubernetes для OpenChamber. Переглядайте кластери, діагностуйте проблеми з робочими навантаженнями й виконуйте типові операції Kubernetes, не залишаючи робочої області проєкту.

## Встановлення

Після публікації зібраних файлів розширення в гілці репозиторію за замовчуванням:

1. В OpenChamber відкрийте **Налаштування → Розширення**.
2. Вставте URL репозиторію в поле **Папка, ZIP або URL** і натисніть **Додати**:

   ```text
   https://github.com/hlhr202/Openchamber-Kubernetes
   ```

3. Перевірте запитаний дозвіл на доступ до локальної служби й надайте його. Потім відкрийте **Kubernetes** на панелі розширень.

Локальне збирання й установлення залежностей JavaScript не потрібні. Поки репозиторій приватний, OpenChamber Server повинен уже мати облікові дані Git для читання репозиторію через HTTPS. Вхід до GitHub у браузері не надає цих даних серверу.

Для [версії-кандидата, перевіреної в Docker](status.md), також є готовий ZIP-архів для ручного встановлення. Встановлення за URL Git ще не перевірено.

## Передумови

- **OpenChamber 2.5.1** — цільова версія цього розширення.
- Робочий **kubeconfig**, доступний користувачеві операційної системи, від імені якого запущено OpenChamber Server. Також потрібні мережевий доступ до API Kubernetes і дозволи на потрібні операції.
- На сервері має бути **`kubectl`**. Для операцій, які викликають Helm CLI, потрібен **Helm**. Якщо kubeconfig використовує зовнішню програму для отримання облікових даних, вона також має бути доступна на сервері. Розширення не встановлює ці інструменти.

## Можливості

- Перемикайте контексти й простори імен Kubernetes, переглядайте робочі навантаження, служби й користувацькі ресурси в дереві ресурсів.
- Переглядайте маніфести ресурсів, журнали Pod і події простору імен.
- Перевіряйте зміни в маніфестах і застосовуйте їх до вибраної цілі лише за явною командою.
- Відкривайте термінал у вибраному контейнері або налаштовуйте перенаправлення портів.
- Переглядайте репозиторії, чарти, релізи та історію ревізій Helm.

## Що перевірив автор

Автор особисто перевірив лише чотири сценарії: розгортання списків у дереві ресурсів, перегляд відомостей про ресурси, роботу з терміналом контейнера й перенаправлення портів. Якщо маєте запитання чи натрапили на проблему в іншому сценарії, [створіть звернення на GitHub](https://github.com/hlhr202/Openchamber-Kubernetes/issues).

## Конфіденційність

- Розширення не надсилає розробникам телеметрію чи аналітичні дані. Воно використовує серверний kubeconfig, щоб підключатися до налаштованого API Kubernetes із вашими наявними дозволами.
- Отримані дані ресурсів, журнали, вивід термінала й незбережені чернетки залишаються в пам’яті й не записуються на диск. Зберігаються нечутливі налаштування, як-от вибір джерел kubeconfig, але не вміст цих файлів. Явне збереження чи експорт — окремі дії.
- Значення об’єктів Secret показуються лише за запитом і в межах ваших дозволів Kubernetes. Дані кластера не надсилаються автоматично в чат або постачальнику моделі.

Ця заява стосується лише розширення, а не OpenChamber, Kubernetes чи зовнішніх інструментів і служб, які ви використовуєте.
